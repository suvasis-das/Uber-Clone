19. Promise — .then() and .catch()

Database connection takes time.

So we handle the result asynchronously.

mongoose.connect(...)
    .then(() => {
        console.log("Connected to DB");
    })
    .catch((err) => {
        console.log(err);
    });

Story

I call the database office.

Then I wait for their answer.

There are two possible results:

Database connection
       ↓
    ┌───────┐
    ↓       ↓
 SUCCESS   FAILURE
    ↓       ↓
 .then()  .catch()

.then()

What to do when the operation succeeds.

.catch()

What to do when the operation fails.

Very important

Don't do this:

.then(console.log("Connected"))

because that executes console.log() immediately.

Do this:

.then(() => {
    console.log("Connected");
})

because .then() needs the instruction/function to execute later.

Memory line

.then() = success
.catch() = failure

20. Current db.js

const mongoose = require('mongoose');

function connectToDb() {

    mongoose.connect(process.env.DB_CONNECT).then(() => {

        console.log("Connected to db");

    }).catch((err) => {

        console.log(err);

    });

}

module.exports = connectToDb;

What this whole file says in English

"Load Mongoose. Create a reusable function called connectToDb. When the function runs, connect to MongoDB using the database URL from the environment variables. If successful, print a success message. If there is an error, print the error. Finally, make this function available to other files."

24. Backend Architecture — Route → Controller → Service → Model

As the project grows, I should NOT put everything in one file.

The work is divided into layers:

Request
   ↓
Route
   ↓
Validation
   ↓
Controller
   ↓
Service
   ↓
Model
   ↓
Database

Real-world story

Think of an Uber company.

Route = receptionist/signboard that sends the visitor to the correct department

Validation = checking desk that checks whether the form is valid

Controller = receptionist who receives the request and coordinates the work

Service = specialist who performs the actual business logic

Model = database worker/interface that works with stored records

Database = records room

Memory line

Route decides WHERE → Controller handles the request → Service does the WORK → Model talks to the database.

45. Important security point — password

The current service receives:

password

and sends it into:

userModel.create(...)

My User model also contains:

password: {
    type: String,
    required: true,
    select: false
}

But remember:

select: false hides the password field from normal reads; it does NOT hash the password.

Password hashing must happen through:

userModel.hashPassword(password)

or another hashing step before saving, depending on where the tutorial puts that responsibility.

Registration security story

Plain password
      ↓
   bcrypt
      ↓
Hashed password
      ↓
   MongoDB

Never store the user's plain password.
