10. Database connection — db/db.js

Code

const mongoose = require('mongoose');

function connectToDb() {

    mongoose.connect(process.env.DB_CONNECT).then(() => {

        console.log("Connected to db");

    }).catch((err) => {

        console.log(err);

    });

}

module.exports = connectToDb;

Understand the code

mongoose.connect(process.env.DB_CONNECT)

Start the connection to MongoDB using the database URL from .env.

.then(() => {
    console.log("Connected to db");
})

Run this after successful connection.

.catch((err) => {
    console.log(err);
})

Run this if connection fails.

module.exports = connectToDb;

Make the connection function available to another file.

Story

connectToDb()
      ↓
Call the records room
      ↓
 ┌───────────────┐
 ↓               ↓
Success         Failure
 ↓               ↓
.then()         .catch()

Important JavaScript lesson

Wrong:

.then(console.log("Connected"))

Why?

Because console.log() executes immediately.

Correct:

.then(() => {
    console.log("Connected");
})

Because .then() receives the instruction/function to execute later.

16. User Model — models/user.model.js

The User model answers two questions:

What does a User look like?

and

What can a User/User model do?

Code

const mongoose = require('mongoose');
const jwt = require('jsonwebtoken');
const bcrypt = require('bcrypt');

const userSchema = new mongoose.Schema({
    fullname: {
        firstname: {
            type: String,
            required: true,
            minlength: [3, "The firstname should be more than 3 characters"]
        },
        lastname: {
            type: String,
            minlength: [3, "The lastname should be more than 3 characters"]
        },
    },

    email: {
        type: String,
        required: true,
        unique: true,
        minlength: [5, "the email should be more than 5 characters"],
    },

    password: {
        type: String,
        required: true,
        select: false,
    },

    socketId: {
        type: String,
    },
});

userSchema.methods.generateAuthToken = function() {
    const token = jwt.sign(
        { _id: this._id },
        process.env.JWT_SECRET
    );

    return token;
};

userSchema.methods.comparePassword = async function(password) {
    return await bcrypt.compare(password, this.password);
};

userSchema.statics.hashPassword = async function(password) {
    return await bcrypt.hash(password, 10);
};

const userModel = mongoose.model('user', userSchema);

module.exports = userModel;

Story

MongoDB is the records room.

userSchema is the User registration form/blueprint.

User
├── fullname
│   ├── firstname
│   └── lastname
├── email
├── password
└── socketId

Then I give an individual User some abilities:

User can:
→ generate an authentication token
→ compare a password

Then I give the User model/system an ability:

User model can:
→ hash a new password

Finally, I create the actual model and export it.

Memory line

Schema = blueprint

Methods = what one User can do

Statics = what the User model can do

Model = tool used to work with User records

17. Mongoose Schema fields

type

type: String

Means the value should be a string/text.

required

required: true

Means the field must be provided.

minlength

minlength: [3, "message"]

Checks the minimum string length and gives a custom message if it fails.

unique

unique: true

Used to create a uniqueness constraint/index for values such as email.

select: false

select: false

The password field is not returned by default when selecting a user.

Story

Think of a registration form:

First Name ★
Email ★
Password 🔒

★ = required

minimum length = form rule

unique email = no duplicate registration

🔒 = password should not normally be exposed

Important password point

select: false does not hash the password.

Password hashing is a separate step using bcrypt.

18. methods vs statics

This is one of the most important concepts.

Methods

userSchema.methods.generateAuthToken = ...
userSchema.methods.comparePassword = ...

Methods belong to an individual User document.

Example:

user.generateAuthToken();
user.comparePassword(password);

Statics

userSchema.statics.hashPassword = ...

Statics belong to the User model itself.

Example:

userModel.hashPassword(password);

Story

Imagine a company.

An individual employee can:

"Generate MY ID card."

"Check MY password."

That is a method.

The HR department can:

"Hash the password for a new employee."

That is a static.

Memory

Methods = MY ability

Statics = COMPANY/User-model ability

19. this

Inside:

userSchema.methods.comparePassword = async function(password) {
    return await bcrypt.compare(password, this.password);
}

this means the current User document on which the method is being called.

Example:

user1.comparePassword(password)

Inside that method:

this

means user1.

If:

user2.comparePassword(password)

then this means user2.

Story

1,000 employees work in the company.

You say:

"Generate MY ID card."

this means:

the person currently speaking.

Memory

this = the current object/document I'm working with.

37. Password security in registration

The plain password should not be stored directly.

The intended security flow is:

User enters password
        ↓
bcrypt.hash()
        ↓
Hashed password
        ↓
MongoDB

Remember:

select: false

only hides the password field from normal queries.

It does not hash the password.

Hashing is a separate step.

Golden Story

My computer is a building. A port is its gate. The HTTP server opens the gate. Express manages the office. Middleware acts as checkpoints. Routes decide where requests go. Controllers are receptionists who handle requests. Services are specialists who perform business logic. Models are database workers. Schemas are their blueprints.
